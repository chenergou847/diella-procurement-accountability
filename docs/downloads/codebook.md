# 编码规则草案 v0.1

日期：2026-10-29。尚未进行正式样本编码，以下是字段及判定规则设计。

## 证据与判断

| 类型 | 含义 | 不能据此推断 |
|---|---|---|
| `source_fact` | 文件身份、发布、记载时间和可读内容已核 | 文件中所有自述都正确 |
| `government_claim` | 机关明确表达的功能、安排或结果主张 | 已实际执行、主张得到独立验证 |
| `institutional_notice` | 法院等主体发布的决定通告 | 超出通告范围的完整裁判效果 |
| `secondary_report` | 可追溯报道载明的引述 | 等同原始实施或验收记录 |
| `research_expectation` | 本文提出、尚待检验的解释 | 已成立的经验发现 |
| `data_gap` | 本研究尚未取得或确认的材料 | 材料不存在或相关行为未发生 |

同一来源可支持多项判断，但多篇转引不自动增加来源独立性。时间字段区分事件发生、文件形成、公开发布和获取时间。不能由发布时间反推系统使用时间。

## 采购模板字段

| 字段 | 说明与规则 |
|---|---|
| `procurement_id` | 原始采购编号；不同来源先去重，再记录关联依据 |
| `agency` / `category` | 采购机构与品类；保存原分类与必要的统一映射 |
| `procedure_type` | 程序类别；记录法律例外，不按名称直接判风险 |
| `budget` / `currency` | 预算及币种；不能直接以预算代替市场基准 |
| `notice_date` / `award_date` | 公告、授标日期；仅在来源可核时填入 |
| `ai_module` / `ai_use_date` | 具体功能及实际使用时间；不以任命或宣传日期填补 |
| `ai_use_evidence` | 将 AI 与该采购关联的记录、出处及证据强度 |
| `recommendation_adopted` | `yes/no/unknown/not_applicable`；无记录不是未采用 |
| `override_reason` | 人工覆盖的理由与来源；不能只记是否覆盖 |
| `bidder_count` | 按统一口径记录实际投标、有效投标或合格投标；不可混用 |
| `single_bidder` | 按预定义口径构造；合法独家供应仍需单独解释 |
| `review_outcome` | 复核机关、理由、决定与执行分别记录 |
| `confirmed_issue` | 指明由谁、按何标准确认何种问题；不自动标为刑事腐败 |
| `final_cost` / `delay_days` | 最终成本与延误；注明基准、变更和观察窗口 |
| `source_ids` | 引用书目或新增来源登记的稳定 ID |
| `missing_reason` | 见下列缺失编码 |

## 缺失与冲突

- `not_disclosed`：有依据判断该信息未公开披露。
- `not_found`：本轮检索未找到，不主张它不存在。
- `unreadable`：文件不可访问、空壳或无法读取。
- `not_applicable`：字段对该项目不适用。
- `conflicting`：来源之间有冲突，暂不强行统一。

未知项不填零。来源冲突保留各原值及选择依据。公开信息只覆盖争议或已发现问题时，样本总体相应收窄。正式编码前须试编并修订歧义；在资源允许时采用独立双人编码与分歧裁定，尚不报告任何一致性系数。
