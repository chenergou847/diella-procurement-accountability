# 如何判断Diella是否使公共采购更廉洁

日期：2026-10-29。本文是可执行的研究方案，不是已经完成的Diella成效评估。主问题保留为“是否更廉洁”，不预设肯定或否定答案。资料和文献编号见[索引](../docs/literature.html)。

## 1. 把研究对象定义到采购流程

建议的目标表述是：在明确时段和采购机构范围内，Diella的特定AI模块，相对于既有电子采购及常规监督，使不当裁量、经核实问题和公共资金损失发生了什么变化？

必须记录每个采购项目：采购编号、机构、品类、预算与规模、程序类型、招标/评审/履约日期；AI模块、真实启用日期、参与阶段与强度；是否有人工复核、修改、推翻及依据。不能用“2025年9月宣布AI部长”替代所有项目的真实处理时间。

处理证据按强弱排序：可追溯模块日志与具体合同关联；签署的操作规程及上线/验收材料；机构明确确认的实际使用范围；最后才是宣传性公告。两轮公开资料溯源仍找不到合同级处理记录时，标为“处理范围未识别”，继续整理测量及机制证据，不虚构处理组。

## 2. 定性研究也可以回答因果问题

定性研究可以完全基于公开资料开展，访谈不是必要条件。制度文本分析、质性内容分析、公开档案的过程追踪和可比采购案例分析，都可以形成研究。资料来源与研究方法应分开：公开资料可以用于定性也可以用于定量，访谈同样不自动构成有效的因果证据。

公开资料优先包括授权文件、采购规则、招标文件版本、修改说明、投诉复核、审计与法院文件及履约公开记录；是否实际取得须逐项核验，不能假定AI内部预警日志均已公开。各类方法的具体步骤和边界见[方法补充](methods.md)。

采用解释性过程追踪，而非只问受访者“你相信AI吗”。可以按采购阶段和风险情境有目的地选择案例，同时纳入预警有效、未预警却出问题、被人工推翻以及正常完成的案例。选择用于机制发现的样本，不假称代表全部采购。

| 待检验机制 | 优先寻找的证据 | 竞争解释与反证 |
|---|---|---|
| AI限制为特定企业设置条件 | 文件版本、生成/修改时间、具体条款、AI建议与人工采用记录 | 条件本来就是依法所需；实际修改由法律改革或人工审查推动 |
| AI提高发现与制止问题能力 | 预警早于纠正，预警原文、复核理由、决定改变及后续结果 | 先有人调查、后来才补AI记录；被标项目本就会被审计 |
| 寻租空间转移或被绕过 | 例外审批、数据修改权限、人工覆盖及履约变更记录 | 合法紧急情况、市场变化、工程设计调整 |
| 问责改善带来约束 | 可识别责任人、独立复核、可执行纠错或制裁及执行记录 | 只增加公开页面，没有实际纠错；责任被分散 |

材料尽量通过采购机关、企业、审计/复核机构等不同来源的公开记录交叉核对，跨机构核对不意味着必须访谈。同一通稿的多次转载不算多份独立证据；未披露也不等于未发生。若有访谈，不能用其代替文件或把受访者共同判断自动视为事实。证据时间顺序、来源独立性、公开选择偏差及与替代解释的区分力，应进入编码表。

可得的结论是“在这些明确案例中，某项AI介入通过某机制改变了某结果”，并说明哪些情境下失效。若要上升为全国净效果，需要进一步样本覆盖、理论外推或量化估计。研究方法依据为[M05](../docs/literature.html#M05)；[D14](../docs/literature.html#D14)仅作为制度角色解释的辅助，不作为已验证反腐机制的证据。

## 3. 定量研究：设计由上线方式决定

先区分描述变化、预测识别与因果效果：风险指数、回归、机器学习或问卷并不自动回答AI是否减少腐败。多元回归和匹配可以帮助调整可观察差异，因果解释仍需额外条件。描述统计、固定效应与匹配、DiD及事件研究、ITS、合成控制、RDD、随机试点和离线识别实验的应用例子与数据要求，见[方法补充](methods.md)。这些设计并非互斥，DiD等也可以用回归估计。

| 实际情形 | 可考虑的设计 | 关键条件 |
|---|---|---|
| 不同采购机构分期上线 | 分组—时间DiD、事件研究、匹配后的比较 | 足够的处理前信息，可比的未处理/尚未处理单位，处理时点与模块可靠；考虑溢出及同期改革 |
| 单位内部有清晰且不易操纵的适用阈值 | 回归不连续或阈值附近比较 | 阈值真实决定AI使用，样本足够、无严重排序操纵，无其他政策同阈值生效 |
| 有尚未扩围的真实试点 | 合法且经有关方同意的随机或分期试点设计 | 这是未来设计，不能把现有观察数据说成随机实验 |
| 全国几乎同时上线 | 可信外部对照、合成控制或有较强条件的时间序列 | 制度口径可比且有较长序列；单纯前后比较通常不足以归因 |
| 只有公开历史文件，没有政府实际使用记录 | 离线、盲评的风险识别实验 | 回答识别能力，不能回答实际部署是否使采购更廉洁 |

分期上线时，可参照[M06](../docs/literature.html#M06)定义组别—时间效应，避免把处理差异压成一个未经检验的全国前后均值。中央采购集中化、法律修订、审计加强、资金结构、通胀、项目品类及市场变化都可能共同影响结果，应事先列出并判断能否分离。

如果AI与中央采购改革完全捆绑、没有可分离变异，最多识别政策组合的效果，不能把全部变化归因于AI。研究中没有找到统计显著变化，也不自动说明没有有意义的效应；需要报告区间、统计功效与可排除的效应规模。

## 4. 主要结局与核验策略

推荐把经独立复核的采购问题发生率或损失测量作为主要结局的候选，具体选择受资料约束。不能承诺在无审计资料时完成真实腐败测量。

| 结局 | 数据与分母 | 需要防止的误读 |
|---|---|---|
| 经独立核实的问题发生率 | 可比抽样采购数中的确认问题数；统一审查标准 | 审计更严格导致发现增加，不等于行为恶化 |
| 限制竞争的风险 | 单一投标、异常资格排除、短期限等；按品类与合法例外调整 | 风险不是已证实腐败；规则被改变也可能让指标表面改善 |
| 成本与交付 | 独立市场/工程基准、最终结算、质量与延迟 | 中标价低于预算不等于损失减少 |
| 纠错与程序责任 | 预警到复核、推翻、申诉处理、补救执行 | 有入口不等于可用；仅记录数量不能替代实际处理 |

参考[M01](../docs/literature.html#M01)、[M04](../docs/literature.html#M04)、[P04](../docs/literature.html#P04)。[A05](../docs/literature.html#A05)说明模型检测可以做定量比较，但应审查训练标签是否只是已有风险规则；预测旧规则与识别真实腐败是不同任务。

独立核验应同时抽取被预警与未被预警、受到AI与未受到AI处理的项目。只核预警项目会产生验证偏差。可采用两名在可行范围内不知处理状态的编码者、预先定义的规则、分歧裁定及来源记录。未被定罪的交易不自动标记为“确定没有腐败”。

## 5. 混合方法：让两类证据相互约束

建议顺序是：先核部署与工作流，定义处理；以少量文件试验编码可得性；选取机制案例做过程追踪；在样本与对照允许时估计效果；最后用独立核验与负例解释结果。

若量化风险下降，但案例发现人工将问题移到合同变更阶段，应扩展结果窗口或收窄结论。若公众信任提高而审计问题不变，应分别报告象征效果与交易效果。若发现案件增加而独立抽样中的问题率下降，则可能同时存在检测增强与行为改善，不能只用发现数量判断方向。

## 6. 适合当前课堂的最低可验证交付

本次先完成资料库、综述与研究设计。后续若开展实证，先进行10–20份公开采购文件的字段/编码可得性试验，这只是试验，不是保证足够的效果评估样本。正式样本量应依据处理机构数量、结局发生率、聚类、变异和目标效应做功效判断。

| 核验项 | 完成标准 | 失败后的处理 |
|---|---|---|
| 部署 | 至少能说明模块、时间、机构，并关联真实采购 | 无法核实则不构造虚假处理组，保存缺口清单 |
| 测量 | 字段、分母、缺失、法律例外和复核规则明确 | 不能用互动量或CPI替代采购廉洁性 |
| 归因 | 竞争解释、共同改革、对照可比性和识别假设可审查 | 若只能描述相关，就明确报告相关 |
| 复核 | 每个关键事实可回到原文件、物理页码或原网页 | 无全文者仅列摘要/线索，不推测结论 |
| 结果 | 正向、负向、混合、零效应和未识别都有报告路径 | 不把资料不足改写成无效，也不预设反腐成功 |

最终应允许四种回答：在限定范围内有改善；有恶化或风险转移；不同环节结果混合；现有资料不足以识别。四者都是研究可能产生的结果，必须由证据决定。
